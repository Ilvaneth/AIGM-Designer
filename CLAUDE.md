## Data root — project-scoped, never the environment

The skill's scripts and hooks resolve campaign data through `paths.py`. Since slice 0 (A0) a copy of the skill inside a project uses **that project** as its data root: `paths.project_root()` walks up from the skill to the folder holding `.claude/`, and if that folder carries `campaigns/` or `.runtime/` the environment is ignored. `DND_CAMPAIGN_ROOT` only decides the root for a plugin or standalone install. The user's machine-wide `setx` value points at the **Ashen Crown** folder and leaks into every tool shell and hook subprocess; before A0 that made this project's edit guard read Ashen Crown's open session. `campaigns/.gitkeep` is committed so the project marker survives a fresh clone (`.runtime/` is gitignored). Check with:

```bash
py .claude/skills/dnd/scripts/paths.py project-root
```

If a script ever reports `ashen-crown` as an active campaign, the project marker is missing; restore `campaigns/` and re-run. Test campaigns generated during development live under `campaigns/_test-*/` (gitignored, plan item 22.6). `.name_registry.json` at the root is kept on purpose: it holds the names Ashen Crown registered from session 38 on, so new campaigns never reuse them (plan items 4.6, 8.7); the earlier Ashen Crown names the owner tired of (Cassivar, Corvina and every Corv-/Corw- derivative, Emberhold, Cinder Choir) are banned outright in `data/design/naming.yaml`'s owner blacklist, beside a list of the model's favourite fantasy names.

Tests: `py .claude/skills/dnd/scripts/run_tests.py` (stdlib `unittest`, discovers `.claude/skills/dnd/tests/`).

## Rules of this project

- Ruleset 2014 (SRD 5.1) only; 2024 support was removed on 2026-09-24 (plan item 21.G). The `**Ruleset:** 2014` state.md header line stays as a harmless stamp.
- Development artifacts (code, tables, plan, commit messages) in English; conversation with the user in Turkish.
- **The narration is Turkish, the world is not** (owner ruling 2026-09-25, errata 24.2 #17): every proper noun a campaign produces — persons, places, institutions, gods, ships, signature phenomena and creatures, months — is an English-language fantasy name, carried into Turkish prose with an apostrophe suffix that follows its last vowel. Common nouns stay Turkish. No word-stem blacklist: uniqueness is on full names and table rows (errata #18). **Since 2026-10-04 (errata #28) a campaign is also *written* in English:** every file a birth produces (bible, dm-only, player files, the owner's cards, table texts) is English and Turkish is spoken at the table only; a named place is never translated. The Turkish-prose reading above holds for legacy births and for play.
- The user's stated rules are the spec: a conflicting upstream behaviour is deleted, never kept as a default.
- **Every campaign is a D&D campaign** (owner, 2026-10-05): every table, rule and output must read as a D&D campaign a DM could run: a threat with a face, a concrete goal and a weakness, dungeons and monsters tied to the threat, three clues per conclusion, a small start. Strangeness is texture, never the engine (`docs/p1-threat-first.md`).
- **Every floor starts with a tag pass** (owner, 2026-10-08, errata 24.2 #33): before a phase from P2 on is built, every row of its tables is tagged under the nine rules of `docs/p1-tags.md` §1, the owner reviews the new topics and clash pairs, and the clash share is measured before and after (zero after). A phase joins the promise ledger only with its tables' reviewed stamps, and a test enforces it. The system is built so that no clash survives.
- **The design tab's reflexes, always** (owner, 2026-10-08): they apply to every input, from the owner, from another tab (a coding tab's question, a draft, a report) or from an agent, whether the owner is present or asleep (he leaves the tab working overnight).
  1. **The better method:** before acting, ask once more whether another method would do it better; weigh the candidates and take the one that fits the system best and fixes the cause for good.
  2. **The sufficiency check:** never wait for the owner to ask "is it enough?". Every proposal or answer (rows, patterns, rules, a specification, an answer to a tab's question) ends with a "Yeterlilik kontrolü": the list of everything it must cover, ticked one by one; what classic D&D (the DMG's lists, the SRD, classic campaigns) has that it lacks; what it leaves in the air for later phases; plainly what was checked, what is missing and what was not checked.
  3. **The last read:** no specification or answer leaves the tab unread: the ids, paths and tables it cites checked by `py docs/tools/spec_refs.py <spec>`; the steps walked in order (each uses only what earlier steps made); every band and count at every scale; no forcing or excluding row leaves a pool empty; the words match the owner's rulings; deleted rows' references named; who writes, commits and approves; no sentence readable two ways. The findings go to the owner before the spec goes out.
  4. **Unattended:** a decision taken while the owner is away stays inside his rulings, takes the recommended option, and is logged with its reasons in the night log (under `docs/reports/`, as `item18-night.md` was) for his review; new work still waits for his yes.
- **Methods that work are shared** (owner, 2026-10-08): `docs/methods.md` collects the audit and test methods that proved themselves (the swap test, the order test, corpus probing, the clean-checkout suite, the ruling-by-ruling diff audit, the reference check, the sufficiency check, the tag pass). It is a catalogue, not a checklist: a tab reads its index and the entries for the task at hand only (the methods that live in the test suite need no reading), and adds a method once it has proved itself. **Every floor's roller gets a swap test** (public output identical whatever the secret records are) and an order test over the whole corpus.
- **The context watch** (owner, 2026-10-08): at every report from a coding tab, the design tab measures that tab's context (`get_usage` with its session id); past 85 % the tab finishes the part in hand and then writes its handoff, before auto-compaction (97 %) can cut a part in two. The design tab watches its own context the same way: past 85 % it tells the owner and writes its handoff. New tabs are opened by the owner only; coding work is never moved into the design tab's own agents.
- **Nothing is hidden from the owner for now** (owner, 2026-10-05): until he says he is sure of the system, secret and villain rows and a test birth's secret layer are shown to him plainly; real births keep the spoiler rule.
- `unittest` (stdlib), run by `scripts/run_tests.py` once it exists; keep the existing hook tests green.
- Commit only when the user asks.
- The development tab never runs a test birth, a playtest, a judge or any model-driven verification (owner, 2026-09-27): it hands the exact instructions to the owner, who carries them to the Opus tab. Model-free tests (the unit suite, regression packs over archived births) run here. Keep token use low: no ultracode-scale workflows.
