# System Register

What actually exists, what has been tested, and what is still missing. Kept honest so the table can tell the difference between *a system that works* and *a system that was written down*.

Governed by `.claude/rules/missing-systems.md` — when play needs something not on the ✅ list, stop and build it before continuing.

**Archived, 2026-09-03**: the Log table below only keeps the most recent 3 distinct dates in full — older entries live in `system-register-archive.md` (same format, full detail), moved there by `py .claude/scripts/log_archive.py ashen-crown --target system-register`. The Core play and Known gaps tables above always reflect current, full status regardless of archiving — only the dated build/fix narrative moves. Re-run the script (`--dry-run` first to preview) once the Log table grows large again.

**Status key**
- ✅ **Built & tested** — exists and has been exercised, either at the table or by direct verification
- 📝 **Built, untested** — written and internally consistent, but never used in play
- ⚠️ **Provisional** — built under time pressure to unblock a scene; works, needs revision
- ❌ **Missing** — known gap, not yet built
