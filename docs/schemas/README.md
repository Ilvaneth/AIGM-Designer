## Conventions every store follows

- **Ids** are `<type>_<slug>`, ASCII, lower case, `[a-z0-9_]`, matching `graph.json`'s convention. Types: `god_ plane_ era_ event_ polity_ region_ settlement_ district_ place_ faction_ npc_ site_ item_ creature_ chapter_ node_ seed_ thread_ socket_ pc_` (errata 24.2 #14) plus five added in slice 0: `premise_` and `arc_` (the campaign-level records the premise and arc files are about), `signature_` and `break_` (risk 24.1 #10: "in ≥3 entities" becomes a count over `refs`), `beat_` (a site's `thread` may point at an arc beat, so beats must resolve). Rooms are not entities. A **secret entity gets an opaque slug** (`npc_s01`) assigned by the phase skeleton; its name exists only in the canonical registry and the dm-only prose.
- **Multi-entity files.** A prose file that holds several entities (cosmology, arc, a settlement with its districts and places) names its own entity in `entity:` and lists the rest under `covers:`; a document that is no entity at all (the primer, the report, the consequence calculus, the generated index) says `entity: none`. The `refs` validator accepts either form.
- **Secrecy** is a closed list on every entity and every news record: `public` / `discoverable` / `secret` (item 11.1).
- **`_meta`** opens every store: `schema_version` (integer, starts at 1), `campaign` (slug), `written_by` (the script and verb that last wrote the file), `written_at` (ISO-8601 UTC), plus store-specific keys named in each doc.
- **Days** are the campaign day counter `calendar.py` keeps (`day-counter`); day 0 is birth, session 1 opens on the start date the cosmology phase fixed. Real-world time never appears in a store except `_meta.written_at`.
- **Writes are atomic**: temp file in the same directory, then `os.replace`; `json.dumps(indent=2, ensure_ascii=False)`, LF line endings, trailing newline. Turkish text is written as-is, never escaped.
- **Stamped fields** are the mechanical form of "the bible is immutable" (item 3): the `stamped` object on an entity is frozen at birth; `registry.py merge` refuses a change to it without a `--revise <log-id>` token and `design_check.py stamps` diffs it against the snapshot at `design/dm-only/_snapshots/stamps.json`.
- **Play-time truth never rewrites a registry field.** Control, ruler, alive/dead/fled, location, status, `seen_in_play`, price modifiers and the threat stage live in the overlay; generated files render registry ⊕ overlay with a "changed since birth" marker (errata 24.2 #2).
- **Fixture flag.** A store whose `_meta.fixture` is `true` belongs to a hand-written test bible; the validator's `scale` module relaxes the count bands for it and nothing else changes.

## The fixture these examples come from

`salt-lantern` (the Salt Lantern): a micro `short` campaign on a salt-marsh coast, one polity, one region, a town and a village, three factions, nine named NPCs (one of them secret, under an opaque slug), four sites (one detailed at birth), one act of three beats in two chapters, two PCs. Sixty-nine registry entities in all; `tests/test_fixture.py` checks the bible the way slice 1's validator will. Below the `short` band on purpose (`_meta.fixture: true`); it exists so every schema has a real instance, so prompt and validator tuning in slice 1 never needs a full birth, and so broken-fixture variants can be derived from it by changing one field each (item 22.1).
