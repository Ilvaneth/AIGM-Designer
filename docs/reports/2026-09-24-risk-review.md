## Synthesizer — strengths to preserve

# Strengths to preserve (any fix above must keep these intact)

1. **Stamped fields as the mechanical form of "immutable" (items 3, 13, 19.3).** `stamped` per entity, `detail` never touching them, `registry.py merge` refusing stamped changes without a `--revise` token, and the validator diffing against the birth snapshot turn a prose promise into a diffable mechanism. Every fix in this synthesis only says which fields sit on which side of that line; none should reintroduce hand-edited canon.

2. **The blind conductor (items 4, 19.1, 19.3, 19.6, 14.4).** Agents return ids, enums, counts and paths only; opaque slugs for secret entities; free text routed through `_staging` and `design_check.py --redact`; approval cards built from the public projection with the `secrecy` validator run on the card itself; explicit `onay` / `devam` gates; `revise --dm-only` reporting only "changed, validator passed". This is the one structural answer to the owner-also-plays problem, and the secrecy fixes above extend it to more channels rather than replacing it.

3. **A deterministic spine (items 7.5, 7.7, 10.5, 19.2, 19.9).** Fronts drive the threat table ("a stage advances when a step completes, not on DM feel"), the arc skeleton is derived by script at P0 (breaking the sites↔arc cycle), assets are map things (a move can only take or break an entity that exists), and every table draw is a labelled, order-independent seeded roll that agents never make. No fix should put DM feel or an LLM decision back into those places — including the simulation engine, which must stay a seeded script with the LLM only narrating.

4. **Data-first registry with wiki-link ids and a front-matter `entity:` line (item 3).** It is what makes the validator, the rename/affected-file scan, index generation, `seen_in_play` and "where does X appear?" mechanical instead of prose-reading. Every structural replacement for the Turkish text scans (enumerated fields, `signature_`/`break_` types with `refs`, `state_after` on beats) builds on it.

5. **The compatibility rule (item 23).** Every new `load`/`save`/`end` step is a clean no-op without `design/`; `simulate` falls back to `tick` by absence of data, not a flag. It is the single decision that lets the designer ship in slices while Ashen Crown keeps playing, and it must be a tested invariant in slice 1, not a note.

6. **The staging protocol and resumable birth (items 19.3-19.4).** Disk is truth, the manifest is the index, prose file first / fragment last, rerun unit = entity once the skeleton is merged, `pending` emitting a 2-hop read budget so no agent reads everything. A multi-hour birth becomes resumable, and each prompt can be tuned on one entity without re-running a phase — the mechanism the build order leans on.

7. **Quality gates as data, and variety by constraint (items 15.2, 18.2, 19.2, 4.1).** A bounded same-model critique loop with rubrics in `rubrics.yaml` (at most two fix loops, then the user, never silent acceptance); script-filtered SRD candidate lists before the LLM chooses; villages in fives, minors and seeds in sixes so one agent differentiates them; theme as a question with the villain and the world embodying opposite answers and the "three sentences that could only be true here" test as the premise gate. These are the anti-mean devices, and the critique pass is the right home for every language-dependent judgement.

8. **How a human DM actually preps and runs (items 1, 10.2-10.3, 13, 9.5, 14.1).** Bible/state split with three pre-written fallbacks per beat so the DM improvises around what happened instead of rewriting canon; `detail` on approach with the between-sessions prep step at `end` and the "detail needed" list printed at `load` and `save`; a site as a graph with minimum depth and a room-by-room progress record that survives compaction. These directly answer the Debased-Mint-unnoticed and Kule-i-Mensuh-built-live failures and should survive every table-friction fix untouched.
